# 럭비두뇌 설명서 (RugbyBrain v1.4.0)

> 감독이 읽는 설명서예요. "두뇌가 지금 아는 것 / 아직 모르는 것"을 칸별로 정리했어요.
> 코드(`rugby-brain.js`)에서 직접 확인한 것만 적었고, 확인이 안 된 건 **⚠ 확인 필요**로 표시했어요.
> 개발자용 쓰는 법은 맨 아래에 있어요.

## 1. 등급별 휠체어 성능 `speedOf(등급)`

등급(0.5~3.5) 하나로 선수 성능 네 가지가 정해져요. 공식은 `c = 등급`일 때:

| 성능 | 공식 | 0.5 | 1.5 | 2.0 | 3.5 |
|---|---|---|---|---|---|
| 최고 속도 (m/s) | 2.3 + 0.9c | 2.75 | 3.65 | 4.1 | 5.45 |
| 가속 (m/s²) | 1.6 + 1.1c | 2.15 | 3.25 | 3.8 | 5.45 |
| 방향 전환 (rad/s) | 2.0 + 0.9c | 2.45 | 3.35 | 3.8 | 5.15 |
| 패스 거리 (m) | 6 + 3.2c | 7.6 | 10.8 | 12.4 | 17.2 |

- **아는 것**: 로우가 출발·방향 전환이 느리고 패스가 짧다는 것. 인바운더 롱패스는 선수 특성으로 따로 줌(`cfg.ibPass=17` 등).
- **모르는 것**: 같은 등급 안의 개인차(체력·기술), 피로, 왼손·오른손. 공식 숫자 자체는 실측이 아니라 감각으로 정한 값 — **⚠ 확인 필요(실제 선수 측정으로 맞추면 좋음)**.

## 2. 공간 계산 `space()` — "누가 먼저 닿는 자리인가"

코트를 0.25m 칸으로 나누고, 칸마다 **가장 먼저 도착하는 선수**를 정해요.

- 도착 시간 = 그 방향으로 몸 돌리는 시간 + 등급별 가속으로 달리는 시간.
- 다른 휠체어는 넘어갈 수 없어서 돌아서 가요(휠체어 반지름 0.62m 기준). 코트 밖은 벽.
- 결과: 선수별 전체 공간 `area`, 상대보다 **0.3초 이상 먼저** 닿는 안전한 공간 `safe`,
  그중 내 베이스라인 쪽 `back`(= 인바운드 받는 공간), 앞쪽 `fwd`.
- 화면 표시 규칙(감독 기준): **범퍼 앞쪽 공간만** 초록으로(`view`, `front`).
  붙어 있는 두 휠체어 중 범퍼가 상대 휠체어에 막힌 선수는 공간 0(`stuck`), 출발에 0.8초 벌점.
- 검증: 감독 PPT '공간이해'처럼 받는 선수가 깊이 내려갈수록 받는 공간이 32 → 21 → 8.5㎡로 줄어드는 걸 재현.

| 두뇌가 아는 것 | 아직 모르는 것 |
|---|---|
| 등급별 가속·방향 전환 | **관성**: 이미 달리고 있는 속도(정지 상태에서 출발한다고 계산) |
| 휠체어끼리 못 지나감, 코트 밖 = 벽 | **공 위치·패스 거리**: 공이 어디 있고 거기서 패스가 닿는지 |
| 범퍼가 막힌 선수 | 갈고리에 걸린 상태, 상대가 막으러 오는 반응 |

## 3. 공격 대형 `ALIGN` / 대형 고르기 `readAlign()`

감독 노션 '26.11.9' 경기분석 그대로(라인업 3.5-1.5-1.5-1.5). 인바운드 직전 공격 1·2·4번 자리.

| 대형 | 자리 | 첫 패스 목표 |
|---|---|---|
| `1set` 1셋 | 1·4번 베이스라인 쪽 같이, 2번 센터라인 위 | 정하지 않음 |
| `2set` 2셋 | 2·4번 같이 센터라인 위 | 2번 (롱패스) |
| `4gull` 4갈메기 | 4번 혼자 센터라인 위 사이드, 2번은 센터라인 바로 아래로 수비를 끌고 내려감 | 4번 |
| `2setlow` 2셋 아래 | 2셋을 센터라인 아래로. 휘슬 뒤 2번이 돌아서 달리고, 4번이 2번 수비 픽 | 2번. 1번→3번 리턴 금지 |

`readAlign()`이 수비를 읽고 고르는 규칙 (`cfg.align='auto'`일 때):

1. 인바체크(인바운더 2.6m 안 수비)가 있거나 센터라인 아래 수비가 3명 이상 →
   인바운더 롱패스가 2셋 2번까지 닿으면 **2셋**, 아니면 **4갈메기**.
2. 아니고 2번이 센터라인 위 → **1셋, 3:2**.
3. 아니면 → **1셋, 4:4** ("2번을 센터라인 위로" 조언).
4. 1번 2m 안에 수비 2명 → "1번 로우트랩 위험, 1번에게 주지 말 것".
- 판단 이유를 `why` 문장으로 같이 돌려줘서 랩에서 보여줘요.

| 두뇌가 아는 것 | 아직 모르는 것 |
|---|---|
| 대형 4개, 인바체크·아래 수비 수·2번 위치로 고르기 | 다른 라인업(예: 3.0-2.0-1.5-1.0)에 맞는 대형 — 노션 라인업 하나만 앎 |
| 인바운더 롱패스 가능 여부 | 상대 선수 성향(누가 인바체크를 잘하는지 등) |
| | 경기 상황(점수·남은 시간)에 따라 대형을 바꾸는 것 |

## 4. 컴퓨터 판단 — 공격

| 상황 | 두뇌가 하는 것 |
|---|---|
| 인바운더 | 휘슬 1.2초 뒤부터 가장 열린 선수에게 패스. 6초가 넘으면 점수가 낮아도 줌, 5.5초 넘게 줄 사람이 없으면 가장 가까운 선수에게 |
| 인바운드 전 리시버 | 정한 자리에서 대기. 0.8초 뒤 패스길이 막히거나 수비가 붙으면 인바운더 패스 거리 안에서 길이 열리는 곳으로 떼고 나옴 |
| 볼맨 | 골 쪽으로 가면서 앞 3.2m 안 수비를 피하고 사이드라인을 피함 |
| 012 작전 | 볼맨 수비가 2명이면 0.25초 뒤 패스(3m 미만 짧은 패스·0.5 선수는 빼고, 아주 좋은 찬스는 예외). 내 수비가 0이면 볼맨 패스 거리 안·볼맨보다 위 공간으로 달리기 |
| 로우가 공을 잡으면 | 0.35초 뒤 옆의 열린 하이·미들(2.0↑)에게 리턴 |
| 12초가 급하면 | 7.5초가 넘으면 앞쪽 열린 선수에게 |
| 막혔을 때 | 1.1초 넘게 막히거나 6.2초 들고 있으면 패스, 줄 데가 없으면 바운스. 수비 1명에 막히면 픽앤롤 시작 |
| 4번(갈고리) | 로우 셋 대상 선수 앞에서 범퍼 지키기(트레일러). 4번이 로우면 센터라인 넘은 뒤 볼맨 스크린 |
| 인바운더(3번) 인바운드 후 | 내 수비 0 → 공간으로 / 내 수비 1↑ + 볼맨 수비 1 → 볼맨 수비 픽 |
| 패스 금지 `passBad()` | 센터라인 넘은 뒤 백코트로 패스 안 함, 2셋 아래에서 1번→3번 리턴 안 함, 1번 로우트랩이면 인바운드 안 줌 |

- **모르는 것**: 수비 대형을 보고 공격 방법을 바꾸는 것(키 수비를 깨는 패턴 등), 시간 끌기·점수 관리, 득점 직전 선택(돌파 vs 패스).

## 5. 컴퓨터 판단 — 수비

설정 `cfg`로 고르는 수비 종류:

| 수비 | 설정 | 두뇌가 하는 것 |
|---|---|---|
| **맨 라인수비** (기본) | `def:'man'` → 내부에서 `manline` | 번호끼리 마크. 마크보다 골 쪽(롱자리)에서 사이드 쪽으로 살짝 쉐이드. 같은 높이의 수비끼리 **라인**(중심 사이 2.25m = 휠체어가 못 지나갈 틈) |
| 인바운드 전 위치 `inPos` | `'11'`(1:1) / `'press'` / `'center'` | 1:1이면 인바운더 담당 수비 등급에 따라 인바체크(1.0↑) 또는 딜레이(0.5) |
| 인바체크 안 할 때 `noIb` | `center` / `trap` / `delay` | 센터라인에서 기다리기 / 리시버 묶기 / 딜레이(인바운드 전엔 센 선수에게 같이 붙고 후엔 인바운더에게) |
| 대형 `form` | `2x2` / `3x1` / `2x1x1` | 인바체크 안 할 때 트랩 대상 정하기 (여기 2x2 등은 **수비** 대형) |
| **라인 프레스** | `inPos:'press'`, `press:'T'/'Y'/'RY'/'auto'` | T = 3명 라인 + 세이프티 / Y = 2명 라인 + 2차 + 세이프티 / 리버스 Y = 로우 2명 베이스라인 앞. auto는 라인업으로 T/Y 고름. 세이프티에 로우는 안 씀. 공격 2명 이상이 라인 위면 맨 라인수비로 |
| **키 수비** | 센터라인 넘고 볼맨이 x>19, 수비 4명 다 x>21이면 자동. `keyDef:'onehead'/'twohead'` | 원헤드(ㅗ): 키 안 코너 2 + 센터 1 + 밖에서 볼맨 따라가는 헤드 1. 투헤드: 센터도 나와서 다음 패스길 막기. 볼맨이 x<13으로 돌아가면 풀림 |
| 다이아몬드 프레스 | `def:'diamond'` | 4번 베이스라인 중앙, 2·3번 양쪽, 1번 깊은 센터 → 코너로 인바운드 허용 후 4번 + 볼 쪽 윙이 트랩 |
| 하이 스위치 | 맨 라인수비일 때 자동 | 상대 하이(2.5↑)가 우리 로우 쪽으로 가면 우리 하이가 넘어가서 막고 마크 교환 |
| 볼맨 어택 | 자동 | 센터라인 넘고 키까지 거리가 4초 동안 안 줄고, 공격시간 20초 이상 남았고, 볼맨이 x<24.5면 → 가장 가까운 수비가 볼맨에게, 나머지는 패스길 디나이 |
| 키 안 수비 3명 제한 | 자동 | 이미 3명이 키 안이면 네 번째는 키 앞에서 멈춤(피하기만 함, 반칙 판정은 없음) |

- **모르는 것**: 상대 공격 패턴을 기억하고 대응하는 것, 체력 안배, 상황별 수비 전환을 감독이 지시하는 것(지금은 설정값 고정 + 몇 가지 자동 전환).

## 6. 픽앤롤

| 종류 | 흐름 |
|---|---|
| 픽앤롤 `startPick()` | 위쪽 가까운 동료가 볼맨 수비에게 감 → 1.4m 안에 붙으면 수비 마크 **스위치** → 0.7초 뒤 픽한 선수가 넓은 공간으로 롤(3초) |
| 리버스 `startReverse()` | 위에 있는 볼맨이 아래쪽 동료 수비를 픽 → 동료가 넓은 공간으로 → 볼맨 수비가 50:50으로 고름(볼맨 따라오면 동료에게 패스, 동료에게 가면 볼맨이 몰고 감) |

- 자동 시작: 볼맨이 0.8초 넘게 막히면(`cfg.pick='auto'`), 또는 볼맨 수비가 1명이고 막힐 때.
- **모르는 것**: 픽 각도·타이밍의 질, 수비가 픽을 미리 보고 피하는 것(파이트오버), 리버스에서 수비 선택이 50:50 고정(상황을 안 봄).

## 7. 물리

| 항목 | 두뇌가 하는 것 |
|---|---|
| 움직임 | 원하는 방향으로 몸을 돌리면서(방향 전환 속도 한도) 가속. 옆으로 가려 하면 덜 빨라짐. 손 놓으면 서서히 멈춤 |
| 후진 | 수비가 2.2m 안의 뒤쪽으로 갈 땐 돌지 않고 후진(최고 속도의 45%) |
| 충돌 | 휠체어 반지름 0.62m. 겹치면 밀어냄. 부딪힌 속도 0.9m/s 이상이면 `hit` 신호(화면 효과·소리용) |
| 버티기 | 멈춰 있는 휠체어를 옆(바퀴)으로 받으면 거의 안 밀림, 범퍼로 받으면 등급 차이만큼 조금 밀림. 상대 범퍼에 정면으로 막히면 속도 55%로 |
| 갈고리 | 수비형 체어(1.5 이하)가 새로 부딪힌 순간 묶일 확률 = 묶이는 선수 등급 × 갈고리 선수 등급 표(예: 3.0을 0.5가 걸면 5%, 1.0을 1.5가 걸면 80%). 멈춰 있으면 1초당 +10%(최대 +30%). 등급 차가 작을수록 오래 묶임(0.5 이하면 그 공격 내내) |
| 트랩 | 1.45m 안에 수비 2명이 90° 이상 벌어져 붙으면 못 움직임 |
| 코트 밖 | 경기 중엔 코트 안(사이드 0.3~14.7)에 묶임, 인바운더만 밖에 |

- **아는 것**: 관성(속도가 서서히 붙고 줄어듦) — 움직임엔 있음. 공간 계산에만 없음.
- **모르는 것**: 실제 마찰·타이어 차이, 부딪혀서 휠체어가 도는 것(회전 충격), 넘어짐, 체력. 갈고리 확률표 숫자는 감독 감각값 — **⚠ 확인 필요**.

## 8. 공

| 항목 | 두뇌가 하는 것 |
|---|---|
| 들고 있는 자리 | 휠체어 중심에서 앞 0.5m, 옆 0.55m (무릎 위) |
| 패스 | 받는 선수가 가는 방향으로 살짝 앞에 던짐. 최대 거리 = 던지는 선수 패스 거리. 공 속도 약 9m/s(최소 0.35초) |
| 가로채기 | 4m 넘는 패스는 70~92% 구간, 짧은 패스는 25~92% 구간에서 수비 0.5m 안이면 턴오버 |
| 잡기 | 30% 이후 공격 0.95m 안이면 잡음 |
| 놓친 공 | 굴러감(3.2m/s에서 점점 느려짐). 코트 밖 → 턴오버, 수비가 먼저 0.85m 안 → 턴오버, 공격이 먼저 → 다시 잡음 |
| 바운스 | 들고 있는 시간을 0으로 |

- **모르는 것**: 공 높이(로브·바운스 패스), 패스 정확도·실수, 잡는 손(오른쪽·왼쪽), 공을 쳐내는 수비(지금은 가로채기만).

## 10. 경기 진행 `match()`

- 4피리어드(기본 8분, `plen`으로 바꿈), 점수, 공수 교대.
- 공격이 끝나면(득점·턴오버·바이올레이션·피리어드 끝) 3.6초 뒤 다음 공격, 상대팀이 공격.
- 후반(3피리어드)에 코트 방향을 바꿔 그림(`flip`).
- 사람이 한 선수를 조종할 수 있음(`human`), 나머지는 AI.
- 공격 시작 전 트랜지션(5~8초, 데드타임): 공격은 사이드라인 한쪽, 수비는 반대쪽에서 들어와 자리 잡음. 등급이 높은 수비일수록 미리 길목을 막을 확률이 높음.
- **모르는 것**: 타임아웃, 선수 교체·라인업 변경(경기 중엔 고정), 연장전, 남은 시간에 따른 작전.

## 11. 장면 `SCENES` / 자리 세우기 `b.setup()`

노션 '26.11.9' 장면 8개를 담아 둠: `1셋 · 2번 위`, `1셋 · 2번 아래`, `인바체크`, `2셋`, `4갈메기`, `프론트 수비 2명`, `1번 로우트랩`, `2셋 아래`.
장면마다 이름·메모·설정(대형, 인바운더 롱패스)·수비 자리가 있음.

- `b.setup(자리)`: 원하는 자리에 선수를 세움(랩에서 끌어 옮기기). 휘슬 전이면 홈 자리도 바뀜.
  `cfg.align='auto'`면 옮긴 수비를 다시 읽어서 공격 1·2·4번을 고른 대형 자리로 옮김.
- **모르는 것**: 노션 다른 날짜 장면들(아직 안 옮김). 장면 저장은 랩 화면(브라우저 저장)이 하고, 두뇌 안 장면은 코드로만 추가.

## 개발자용: 쓰는 법

엔진이 보내는 신호(`event`): `hit`(휠체어 충돌, power=부딪힌 속도), `pass`, `catch`, `bounce`, `whistle`, `inbound`, `switch`, `hook`, `pick`, `possEnd`(공격 끝, good=득점), `final` 등. 화면 효과·소리는 이 신호로 붙여요.

```html
<script src="../engine/rugby-brain.js"></script>
<script>
const m = RugbyBrain.match({
  plen: 180,                                  // 피리어드 길이(초), 4피리어드
  lines: { B: ['3.0','3.0','1.0','1.0'], R: ['3.0','2.0','2.0','1.0'] },
  human: { team: 'B', num: 1 },               // 사람이 조종할 선수 (null이면 전원 AI)
  input: () => ({ x: 0, y: 0 }),              // 화면 기준 조이스틱 (오른쪽 +x, 아래 +y)
  msg: (text, ms) => {},                      // "휘슬!", "득점!" 같은 안내
});
m.start();
// 매 프레임: m.step(dt); 그리고 m.brain.G 를 읽어서 그리기
// 버튼: m.pass(), m.pass('A2'), m.bounce(), m.setHuman({team:'B',num:3})
</script>
```

공격 한 번만 돌리기(랩처럼):

```js
const b = RugbyBrain.create({ cfg: { align: 'auto', ibPass: 17 } });
b.newGame();
b.setup(RugbyBrain.SCENES[2].pos);   // 장면 세우기
b.whistle();                         // 또는 cfg.autoWhistle (기본: 1초 뒤 자동 휘슬)
// 매 프레임 b.tick(dt); b.G.ps(선수), b.G.ball(공), b.G.phase('ready'|'live'|'over')
const sp = b.space();                // 공간 계산 → sp.view, sp.front, sp.stuck
const rd = b.readAlign({ sp });      // 대형 판단 → rd.rec, rd.play, rd.why
```

코트 그리기(`rugby-court.js`):

```js
RugbyCourt.SPEC                 // {L:28, W:15, key:{d:1.75,w:8}, goalW:8, circleR:1.75, ...}
RugbyCourt.draw2d(ctx)          // 캔버스 2D (ctx는 1단위=1m로 변환해 둘 것)
RugbyCourt.drawPixi(graphics)   // PixiJS
RugbyCourt.keyRect('right')     // 키 에어리어 사각형
```

- `m.flip`이 true면 화면에서 좌우를 뒤집어 그려요.
- Node에서도 `require('./rugby-brain.js')`로 화면 없이 수백 판 돌릴 수 있어요.
- 키 규격은 두뇌 `RugbyBrain.KEY`(판정)와 `RugbyCourt.SPEC.key`(그림) 두 곳에 있어요. 둘 다 불러오면 숫자가 다를 때 콘솔에 경고가 떠요.
